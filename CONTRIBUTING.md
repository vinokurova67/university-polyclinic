# Правила командной работы

## 1. Основная ветка
Основная ветка проекта — main.
В ней хранятся согласованные и проверенные материалы.

## 2. Рабочие ветки
Для выполнения отдельных задач создаются тематические ветки:
- docs/ — документация;
- diagrams/ — диаграммы;
- requirements/ — требования;
- fix/ — исправления.

## 3. Коммиты
Каждый коммит должен отражать конкретное изменение.
Сообщения коммитов должны кратко описывать выполненную работу.

Примеры:
- Добавлены требования к системе;
- Обновлена диаграмма последовательности;
- Исправлены ссылки в README.

## 4. Проверка изменений
Перед слиянием изменений другой участник команды
проверяет изменённые файлы, их содержание и соответствие
требованиям проекта.

Автор изменений не заменяет проверку другого участника
собственной отметкой.

## 5. Запросы на слияние
Для объединения изменений используется Pull Request.
В описании указываются:
- цель изменения;
- изменённые файлы;
- связанные требования и варианты использования;
- результаты проверки.

## 6. Актуальность документации
Основной редактируемый вариант отчётов — Markdown.
Word-версии обновляются после согласования Markdown
и перед сдачей практических работ.

Исходники диаграмм и соответствующие изображения
обновляются одновременно.

## 7. Ответственный за Word-версии
Ответственный за подготовку и проверку Word-версий
назначается командой перед сдачей.

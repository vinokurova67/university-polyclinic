# Практическая работа № 4. Организация Git-репозитория проекта

## 1. Цель работы
Освоить организацию репозитория программного проекта и базовый цикл командной работы с Git: получение проекта, создание ветки, фиксацию изменений, отправку на площадку, взаимную проверку и слияние.

## 2. Выбранная площадка и обоснование выбора
Для размещения репозитория выбрана платформа **GitHub** (https://github.com/vinokurova67/university-polyclinic). 
**Обоснование выбора:** GitHub предоставляет бесплатный хостинг для Git-репозиториев, поддерживает ветки, запросы на слияние (Pull Requests), позволяет гибко настраивать права доступа для участников команды и преподавателя, а также имеет удобный веб-интерфейс для просмотра истории изменений и обсуждения правок.

## 3. Структура репозитория и пояснения к размещению материалов

В соответствии с заданием в корне репозитория создана следующая структура:

- `README.md` — корневой файл с описанием проекта и навигацией.
- `.gitignore` — правила исключения временных файлов (например, `~$*.docx`).
- `CONTRIBUTING.md` — правила командной работы (ветки, коммиты, проверка).
- `source-material/` — исходные материалы, предоставленные преподавателем.
- `docs/` — документация и отчетность:
  - `README.md` — полный общий отчет команды (Markdown).
  - `report.docx` — общий отчет Word для сдачи (пока может быть в процессе подготовки).
  - `doc/` — индивидуальные отчеты Word участников.
  - `md/` — индивидуальные отчеты Markdown участников.
  - `img/` — изображения для отчетов (PNG, JPG).
  - `draw/` — редактируемые исходники диаграмм (`.drawio`, `.puml`).
- `projects/` — программная часть продукта (пока содержит `.gitkeep` и `README.md`).
- `modules/` — отдельные модули системы (пока пусто, добавлен `README.md`).
- `tests/` — тесты (пока пусто, добавлен `README.md`).
- `teams/` — сведения о команде и ролях.

**Правило актуальности документов разных форматов:**
Содержание отчетов изменяется в Markdown-файлах (`docs/README.md`, `docs/md/...`). Word-версии (`docs/report.docx`, `docs/doc/...`) обновляются после согласования Markdown и перед каждой сдачей. Исходник диаграммы (`docs/draw/`) и её изображение (`docs/img/`) обновляются одновременно. Если содержательная правка впервые сделана в Word, она переносится в Markdown и повторно экспортируется в Word.
